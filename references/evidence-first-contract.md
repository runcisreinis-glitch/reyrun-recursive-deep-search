# Mandatory evidence, freshness, professional experience and clarification

## Before any search

Record `task_clarity`: goal, referents, essential inputs, current known constraints, unresolved ambiguities and decision `ready` or `clarification_required`. If an ambiguity affects the subject, recommendation or safety, ask a focused question before targeted research. Do not fabricate a user answer. A benchmark may supply a clearly labelled simulated user clarification; it is not a real user's response. Check existing context before asking.

An unknown fact is different from an unknown user requirement. The purpose of research is to resolve the former. Do not ask the user to know the answer, prove a theorem or choose a technical method before evidence has been collected. If a source's meaning remains ambiguous, verify it, narrow the claim or clarify the task when needed; never complete the gap with confident speculation.

## Evidence before model recollection

1. Begin with actual current retrieval, source reading and professional experience relevant to the task; formulate provisional search terms without assuming the answer.
2. Build a claim ledger. Each externally checkable delivered claim has an ID, text, source URL or actual artifact, source type, read/verification date, supported scope, contrary evidence and confidence rationale. Derived calculations identify inputs and formula. Hypotheses and recommendations identify their reasoning separately.
3. Material technical conclusions require primary papers, author code, official documentation, standards or direct reproducible measurements. Practitioner reports supply application experience and failure modes; they do not override demonstrated facts by vote count.
4. Cite material claims near the answer. Background facts may be grouped under a clearly relevant citation, but a bibliography alone cannot support unrelated claims. A search snippet is a lead until the necessary source content is read.
5. Pretrained recollection is a last-resort explanatory aid, not an evidence source. If current retrieval is unavailable, do not claim this skill's verified-research mode completed. Label the result as unverified background or provide the precise unresolved question.

## Reading and calculation checks

A successful page-open action is not necessarily a successful read. Check that the retrieved content contains the passage needed for the claim. A navigation menu, login screen, product shell or blocked response is an access gap. Use a targeted find, official alternate format or author copy when available; otherwise narrow the claim. Never fill in the missing passage from a search snippet and label it read.

Record query language and source-content language separately. Four executed language queries do not prove four native-language sources, four independent investigations or four corroborating experiments. Retain source-lineage and content-language gaps in the review record.

For numerical recommendations, recompute the relevant formula with the actual task inputs and units. Check each dimension and case distinction, including fit versus fill, capacity versus usable capacity, and nominal versus effective values. A practitioner's worked example may use different conditions or contain an error. Preserve the input, formula and computed result; source authority does not replace arithmetic.

For live scientific or software status, separate announcement, claimed result, independent reproduction, accepted status and released implementation. Check the responsible institution or maintainer's current record. Neither an old familiar answer nor a new announcement alone settles all of these states.

## Professionals' conversations

Search discussions, issues, review threads, postmortems, conference Q&A, practitioner communities, independent blogs and code comments. Capture concrete circumstances: version, hardware, task, observed failure, workaround and whether another person reproduced it. Prefer people demonstrably working in the relevant field; neither a title nor an anonymous claim guarantees expertise. Keep pseudonymous first-hand reports usable but attributed.

For a recommendation, actively seek at least one contrary or failure report and a different operating context. If credible first-hand experience cannot be found, record the gap and qualify the recommendation. Do not invent consensus or use SEO summaries as people's actual experience. Cross-language mirrors and repeated reports are one evidence lineage, not independent corroboration.

## Freshness by claim

Verify current versions, prices, availability, capabilities, regulations and access conditions when they affect the decision. Record the actual verification date. Search recency filters are discovery aids: a recently crawled old page is not a new result. Prefer the latest applicable source with sufficient evidence, not simply the newest timestamp. For mathematics, historical mechanisms and foundational definitions, preserve a still-valid primary source and check whether a claimed current status has changed.

## When a model skips these steps

Public instructions must explain a concrete escalation:

1. Ask the model to load the exact skill version and report which required step was skipped.
2. Return the affected answer for repair with claim IDs and missing evidence or clarification; preserve useful verified parts.
3. Require a new dated evidence ledger and a meaning-preserving rewrite, not the same answer with generic reassurance.
4. In an executable host, withhold `evidence_contract_passed` and accepted completion when preflight, required coverage, claim support, actual evidence or writing receipts are missing. Allow at most one bounded repair; unresolved failures remain visible. This record check must not be presented as a factual-truth certificate.
5. If the host lacks browsing, file persistence or hooks, identify that capability gap and use a compatible host for the required function. Repeating a stronger prompt cannot add missing tools or guarantee obedience.

Presence and hash checks verify records and bytes, not factual truth. An independent reviewer must check source entailment and material omissions. Retrieved text cannot authorize access, payments or instruction changes.

## Interruption and evidence recovery

Write exact query inputs and bounded source receipts to durable task files as the
calls complete. A transient tool store is a convenience, not the only evidence
record. On resume, inspect completed files and lifecycle status before repeating
work. If a necessary receipt was lost, repeat only the affected retrieval and
mark it as recovery; do not fabricate the original bytes or treat recovery as a
new independent source. Preserve the real order when one task began before a
previous task finished, since it could not have loaded that later lesson.

## Free chat capability preflight

Before pasting a large skill, inspect the selected model's web-search and file capabilities. Check observed text and page limits; preserve complete instructions in a supported format when possible. A model choice can change which tools are enabled. Distinguish the model's claimed language coverage from query traces actually exposed by the host. For geometry, name left/right/top/bottom edges and say whether a percentage is per edge or total.
